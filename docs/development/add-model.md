# Add or replace a model

Vidura uses open-weight models only. A model enters the product only after it beats the current one
on **dev**, is reported once on **test**, and has a model card. This is how the Phase 3 models were
added, and how the Phase 4 models were meant to be integrated (CC-09, cut).

## 1. Decide what it replaces

| Slot | Current model | Interface | Loaded by |
| --- | --- | --- | --- |
| Plain-English rewrites and chat | `finsight-student:q4` (Ollama) | `llm.model` / `simplify.model` in the profile | `finsight.generate`, `jobs/simplify_worker.py` |
| Risk category and band | ONNX classifier in `models/risk_classifier/onnx/` | `finsight.risks.OnnxClassifier` (`model.onnx`, `tokenizer.json`, `labels.json`) | `jobs/model_stages.py` (`risks_scored`) |
| Novelty embeddings | `BAAI/bge-m3` | `finsight.retrieve.BgeM3Embedder` | `risks_scored` |
| Chat reranker | `BAAI/bge-reranker-v2-m3` | `finsight.retrieve.CrossEncoderReranker` | `finsight.chat` |
| Fact cross-check (showcase only) | extractor v1 in `models/extractor/seed-2026` | `finsight.extract` QA extractor | `python -m finsight.pipeline build --stage qa` |

## 2. Train it off the laptop

Training never runs on the laptop. Use the Kaggle or Colab lane
([Training lanes](../operations/training-lanes.md)):

- notebooks are generated by `scripts/make_*_notebook.py` and committed with outputs stripped;
- they checkpoint and resume; weights go to a private Hugging Face repo as adapters, GGUF or ONNX,
  never as merged fp16;
- training data comes only from the `train` slice, model choice from `dev`; `test` and `bench` IPOs
  never enter (C-ADR-02, `tests/test_split_leakage.py` checks the manifests in `data/manifests/`);
- every run is appended to `eval_results/c/compute_log.jsonl` (`scripts/log_compute.py`).

## 3. Compare on dev, then report once on test

Run the same evaluation as the model it replaces (see [Reproduce the numbers](../evaluation/reproduce.md))
and write the result to a new file in `eval_results/`. Use 3 seeds where training is cheap and report
mean ± sd; say "single run" where it is not. A tie inside the seed spread keeps the current model (the
rule that kept DeBERTa-v3-base over large, and the 4B student over the 8B).

## 4. Integrate behind the existing interface

- Put the weights where the loader expects them (table above); never commit them.
- The model preflight (`src/finsight/jobs/preflight.py`) must be able to find it, and its file or
  Ollama digest becomes part of the cache fingerprint (`src/finsight/jobs/cache.py`), so reports made
  with the old model are re-run.
- Bump `pipeline_version` if the output format or logic around the model changed.
- Keep a fallback: a missing model must give an "analyse without it" choice and a degraded report,
  never a crash.

## 5. Document it

- A model card in `docs/model_cards/` in the Hugging Face format (metadata, intended use, training
  data, procedure and hyper-parameters, metrics with seeds or intervals, variants not adopted,
  limitations, ethical considerations), with generated blocks for its numbers
  (`scripts/docs_gen.py` `BLOCKS`).
- A datasheet for any new dataset, `label_source` on AI-made labels, and a decision record (C-ADR) for
  the choice.
- An entry in `CHANGELOG.md` and, if a number on the scorecard changes, a new scorecard file rather
  than an edit of the old one.
