# Developer guide

## Repository layout

```text
src/finsight/<package>/   Python packages, one job each (see Architecture)
tests/<package>/          pytest tests, mirroring src/
configs/                  YAML settings, rules, thresholds and the frozen split
scripts/                  one-off and evaluation scripts, docs generators
notebooks/                Kaggle and Colab training notebooks (generated by scripts/make_*_notebook.py)
frontend/                 Next.js web app
docs/                     this site; planning records of each phase; docs/archive/
eval_results/             every measured number (the record)
bench/v1/                 FinSight Bench v1 (frozen inputs)
data/                     local only (gitignored), except data/gold/ and data/manifests/
models/                   weights, local only (gitignored)
ml/                       Phase 4 ML lane and hand-off pack (unused by the product)
deploy/                   Ollama Modelfile; a dormant Space README
```

## Set up

Follow [Install](../getting-started/install.md), then add the docs group:

```bash
uv sync --inexact --group ml --group onnx --group docs
cd frontend && pnpm install --frozen-lockfile
```

## Coding standards

- Python 3.11, typed. `ruff` (line length 100; rules E, F, I, UP, B, SIM, PT, RUF) and `ruff format`;
  `mypy` on the correctness-critical packages (`uv run poe typecheck`).
- Pydantic v2 schemas live in `finsight.core.schemas`; packages import each other only through their
  `__init__.py`.
- Google-style docstrings on public functions; each package's `__init__` docstring states its job.
  CI fails below 70 % docstring coverage (`interrogate`) and warns below 80 %.
- Paths with `pathlib`, LF line endings (pre-commit enforces them), UTF-8.
- No investment advice anywhere: user-facing text is checked against
  `configs/forbidden_phrases.yaml`, and the risk level always carries its disclaimer.
- Frontend: TypeScript strict, ESLint, components in `components/<screen>/`, logic in `lib/` with a
  test file beside it, copy in `lib/content/` ([Frontend](../architecture/frontend.md)).

Pre-commit runs end-of-file, trailing-whitespace, mixed-line-ending, YAML, merge-conflict and
large-file checks, ruff, ruff format and `nbstripout`:

```bash
uvx pre-commit install
```

## Tests

| Command | Runs |
| --- | --- |
| `uv run poe test` | fast suite: everything not marked `slow`, `local` or `postgres` (what CI runs) |
| `uv run poe test-all` | everything, including real models and full documents |
| `uv run pytest -m local` | tests that need `data/processed`, full PDFs, the corpus or weights |
| `uv run pytest -m postgres` | needs `FINSIGHT_TEST_PG_URL` (CI uses a service container) |
| `uv run poe lint`, `uv run poe typecheck` | ruff and mypy |
| `cd frontend && pnpm test` | Vitest |
| `cd frontend && pnpm test:e2e` | Playwright on the mocks; `E2E_REAL=1` against the running app |

Rules: every module ships with tests; `normalize` has property tests (Hypothesis); a test that needs a
real document or weights is marked `local`. `tests/test_split_leakage.py` guards the time split.

## CI

Three GitHub Actions workflows run on pushes to `main` and on pull requests:

| Workflow | Jobs |
| --- | --- |
| `backend.yml` | `uv sync --locked --group onnx`, lint, typecheck, fast tests; a Postgres job runs `pytest -m postgres` |
| `frontend.yml` | Node 24, `pnpm install --frozen-lockfile`, lint, typecheck, Vitest, build; Playwright in a second job |
| `docs.yml` | generated pages current (`docs-gen --check`), `openapi.json` current, strict site build, docstring floor, Markdown lint, link check |

## Branches and pull requests

Issue → branch `<type>/<part>-<slug>` → small commits in Conventional Commits style → pull request →
CI green → merge → delete the branch. Phase 1–3 work used rebase-merge; Phase 4 branches used merge
commits so the second agent's commits kept their SHAs. Never force-push `main`; never commit data
(except `data/gold/`, `data/manifests/` and the fixture pack), weights, PDFs, `.env` or files over
5 MB. The full rules are in
[08_GIT_WORKFLOW.md](https://github.com/AkshatTm/FinSight-IPO-X-Ray-for-Indian-retail-investors/blob/main/docs/08_GIT_WORKFLOW.md)
and the [contributing guide](https://github.com/AkshatTm/FinSight-IPO-X-Ray-for-Indian-retail-investors/blob/main/CONTRIBUTING.md).

## Docs

Docs change in the same pull request as the behaviour they describe. Numbers are never typed by hand.

```bash
uv run poe docs-gen          # rewrite generated pages and blocks (config, ADR index, glossary, model cards …)
uv run poe docs-gen --check  # fail if a committed page is stale (CI)
uv run poe gen-openapi       # openapi.json from the FastAPI app; then: cd frontend && pnpm gen:api
uv run python scripts/readme_results.py   # the README results table from eval_results/
uv run poe docs-build        # mkdocs build --strict into site/
uv run poe docs              # serve on :8000
uv run python scripts/check_links.py      # dead relative links in every Markdown file
```

`scripts/docs_gen.py` owns these pages: `reference/config.md`, `reference/configs.md`,
`reference/redflags.md`, `reference/risklevel.md`, `reference/compare.md`, `reference/cli.md`,
`reference/data_formats.md`, `adr/index.md` and `glossary.md`, plus the blocks between
`<!-- generated:NAME start -->` and `end` markers on the evaluation page, model cards and datasheets.
Edit the source (a YAML file, a decision log, a result file), not the generated text.

## Common changes

- [Add a red-flag check](add-redflag-check.md)
- [Add or replace a model](add-model.md)
- **Add a fact-sheet field.** Describe it in `configs/fields.yaml` (`id`, `label_en`, `type`, `doc`,
  `sections`, `questions`, `extractor`, `fallback`, `ladder`); write the rule in
  `src/finsight/extract/rules.py` using `finsight.normalize.parse_amount` so lakh, crore, million and
  `[●]` are handled the same way; test it in `tests/extract/test_rules.py` (including a `[●]`
  placeholder and a sentence that must not match); add the field to the gold template and leave the
  gold value to a person; rebuild a showcase IPO (`--stage rules`, then `--stage xray`) and check the
  page chip lands on the right words. `label_hi` still exists in the file but is not shown since v1.1.
- **Change extraction, red-flag or risk-level logic.** Bump `pipeline_version` in
  `configs/config.yaml` so stored reports are re-analysed ([cache key](../architecture/pipeline.md#cache-key-and-pipeline-version)).
- **Change the API.** Update the route and its Pydantic model, run `uv run poe gen-openapi` and
  `pnpm gen:api`, and update the [API guide](../reference/api-guide.md).
