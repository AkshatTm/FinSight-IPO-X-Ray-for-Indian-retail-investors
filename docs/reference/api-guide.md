# API guide

The FastAPI service listens on `http://127.0.0.1:8000`. All routes are under `/api`. The full schema is
the [OpenAPI reference](api.md) (`openapi.json`, generated by `uv run poe gen-openapi`); the
interactive docs are at <http://127.0.0.1:8000/docs> while the API runs.

On the laptop there is no sign-in: requests without an `Authorization` header act as the one local user.
Errors share one shape:

```json
{"error": {"code": "not_found", "message": "…", "hint": "…"}}
```

Every command on this page was run against the v1.1 API (profile `local`) on 12 Nov 2026: the reads on
a stored upload and on the Ather Energy showcase, the upload, re-analyse and delete on a synthetic test
PDF (refused at `validated` as `not_offer_document`, as expected), and two chat questions.

The examples use Git Bash. Set the base URL once:

```bash
API=http://127.0.0.1:8000/api
```

## Health

```bash
curl -s $API/health
```

`status` is `ok`, `warming` (models loading) or `degraded`, with the profile, demo mode and each
model's state.

## Upload a document

Three calls: register the file by its hash, send the bytes, then start the analysis.

```bash
PDF=my-rhp.pdf
SHA=$(sha256sum "$PDF" | cut -d' ' -f1)
SIZE=$(stat -c%s "$PDF")

curl -s -X POST $API/uploads/init -H 'content-type: application/json' \
  -d "{\"filename\": \"$PDF\", \"size_bytes\": $SIZE, \"sha256\": \"$SHA\"}"
# {"status": "upload", "doc_id": "doc_…", "upload_url": "/api/uploads/doc_…/file", "upload_method": "POST", …}
# or {"status": "exists", "doc_id": "doc_…"} when this file was already analysed

DOC=doc_$(echo $SHA | cut -c1-16)
curl -s -X POST $API/uploads/$DOC/file -H 'content-type: application/pdf' --data-binary @"$PDF"
curl -s -X POST $API/uploads/$DOC/complete -H 'content-type: application/json' -d '{}'
# {"doc_id": "doc_…", "job_id": "…", "status": "queued"}
```

If a model is missing, `complete` answers `503 models_unavailable` and names it. Start the model, or
analyse without it: `-d '{"analyse_without": ["ollama"]}'` (values: `ollama`, `classifier`,
`embeddings`, `reranker`).

The API refuses with `422 too_large` or `422 hash_mismatch`, `429 quota_exceeded` (or
`global_quota_exceeded`), `503 uploads_disabled`, and `409 upload_not_started` when the file has not
arrived. The PDF itself is checked inside the job: a scanned, password-protected or non-offer document
ends with a failed `validated` stage, for example
`{"stage": "validated", "status": "failed", "detail": {"reason": "not_offer_document"}}`, and the
document row's `status` is `failed`.

## Follow the analysis

```bash
curl -N $API/docs/$DOC/events          # server-sent events until "done"
curl -s $API/docs/$DOC                 # the document row, its stages and cache state
```

Events are `stage` (start / end / failed), `ready` (a report part can be shown), `risk_simplified`
and `done`. Reconnect with the `Last-Event-ID` header to resume.

## Read the results

```bash
curl -s $API/docs/$DOC/report          # overview: facts, sod, risk level, top risks, flags at a glance
curl -s $API/docs/$DOC/redflags        # 13 checks and serious findings
curl -s $API/docs/$DOC/risk-level      # level, score, reasons, disclaimer
curl -s $API/docs/$DOC/risks           # every risk factor (category, seriousness, novelty, rewrite)
curl -s $API/docs/$DOC/compare         # listed peers and past-IPO reference
curl -s $API/me/uploads                # everything you uploaded
```

`GET /report` supports `If-None-Match` with the ETag it returns.

Ask for a plain-English rewrite of one risk (moves it to the front of the queue):

```bash
curl -s -X POST $API/docs/$DOC/risks/<rid>/simplify
```

## Re-analyse or delete

```bash
curl -s -X POST $API/docs/$DOC/reanalyse -H 'content-type: application/json' -d '{}'
curl -s -X DELETE $API/docs/$DOC
```

`reanalyse` clears the stored analysis and starts a new job on the stored PDF; it takes the same
`analyse_without` list. `DELETE` removes the files, page images, search index and rows.

## Chat

```bash
curl -N -X POST $API/chat -H 'content-type: application/json' \
  -d '{"ipo_id": "ather-energy-2025", "question": "How much money is the company raising?"}'
```

The answer streams as server-sent events in this order: `stage` (guard, retrieving, generating,
verifying; each `start` / `end` with `ms`), `retrieval` (the passages and pages), `token` (the draft),
`answer` (the checked text with its citations, which replaces the draft), `verdict` (one per number in
the answer: `verified`, `unverifiable`, `contradicted`) and `final` with a `trace_id`, `n_numbers` and
timings (`GET /api/traces/{trace_id}`). An advice question gets a `guard` event and `final` before any
retrieval; a question whose best passage scores too low gets `abstain` and `final`. A failure is one
`error` event. An answer without numbers has no `verdict` events. Answers are English; `language` and `source` fields from
older clients are accepted and ignored.

## Showcase IPOs and the lab

```bash
curl -s $API/ipos                                  # the library
curl -s $API/ipos/ather-energy-2025/xray           # the fact sheet with pages and boxes
curl -s $API/ipos/ather-energy-2025/suggested-questions
curl -s $API/glossary

```
